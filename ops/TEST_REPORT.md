- ❌ Does NOT prove: that a real Attio workspace with the exact attribute
  slugs assumed in `worker/src/adapters/attio.ts` (`ATTRS` object) exists,
  or that a real beehiiv publication ID/API-write plan is active. Those
  need the controlled TEST-record smoke tests in guide §41–42, which are
  BLOCKED on account creation (see `ops/SETUP_STATUS.md`).

## 2026-08-21 — Worker unit tests (mocked adapters)

Added `vitest` (`worker/vitest.config.ts`, `worker/src/*.test.ts`) per guide
§40 ("External API calls in automated tests should be mocked"). Both Attio
and beehiiv adapters are mocked with `vi.mock` — these tests never touch a
real network.

| Suite                         | Command               | Result                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `validate.test.ts` (10 cases) | `npm run worker:test` | ✅ all pass — required-field, email-format, product-enum, honeypot, HTML-stripping, and UTM pass-through/omission behaviour all confirmed                                                                                                                                                                                                                                                      |
| `index.test.ts` (9 cases)     | `npm run worker:test` | ✅ all pass — static-asset fallback, unknown-route 404, valid enquiry → Attio adapter called, invalid enquiry → 400 without calling Attio, **adapter throw → 502 with the raw error message NOT present in the client response (confirms guide §64's no-leak rule with an actual assertion, not just a code read)**, valid subscribe → beehiiv adapter called, honeypot → beehiiv never called |

Wired into CI: `.github/workflows/ci.yml`'s `checks` job now runs
`npm run worker:check` and `npm run worker:test` alongside the existing
site checks — a broken Worker fails CI the same way a broken site build
does.

This closes the "is the routing/validation/error-handling logic actually
correct" question with 19 passing assertions, independent of whether Attio/
beehiiv accounts exist. It does **not** close the "are the real Attio
attribute slugs and beehiiv publication ID correct" question — that's still
gated on the real-account smoke tests above.
